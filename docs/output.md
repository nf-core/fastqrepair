# nf-core/fastqrepair: Output

## Introduction

This document describes the output produced by the pipeline.

## Pipeline overview

The nf-core/fastqrepair pipeline is built using [Nextflow](https://www.nextflow.io/). Output files are gathered into the `repaired` subfolder of the output folder set up using the `--outdir` command line parameter.

```
<output folder>
  - pipeline_info/
  - QC/
    - fastqc/
    - fq_lint/
    - multiqc/
  - repaired/
  - repaired_samplesheet.csv
```

<details markdown="1">
<summary>Folders content</summary>

- `pipeline_info` contains report metrics generated during the [workflow execution](#pipeline-information)
- `QC` contains the [fq lint](#fq-lint) status of the samples, [FastQC](#fastqc) QC analysis results and [MultiQC](#multiqc) reports
- `repaired` contains the fastq files of all the samples and the quality reports of the repaired ones
  - `mysampleA_1.fastq.gz` (and `mysampleA_2.fastq.gz`) are the repaired fastq files of a paired-end sample, `mysampleC.fastq.gz` that of a single-end sample
  - `mysampleA_1.report` (and `mysampleA_2.report`) are the summaries of the cleaning task
  - the samples that passed [fq lint](#fq-lint) were not repaired: their reads are only copied here (compressed, if they were not), with the same names and without a report
- `repaired_samplesheet.csv` is the [samplesheet of the reads in `repaired`](#repaired-samplesheet)

</details>

### fq lint

Unless `--skip_fq_lint` is used, the input reads are checked with [fq lint](https://github.com/stjude-rust-labs/fq) before anything else. The samples that pass the check are not repaired, which saves the repair of large files that are fine. A sample is only skipped when its fq lint log looks clean: if the check fails or cannot run, the sample is repaired as usual. Skipped samples still get a FastQC and a MultiQC report.

<details markdown="1">
<summary>Output files</summary>

- `QC/fq_lint/`
  - `fq_lint_status_mqc.tsv`: for each sample, whether it `passed` or `failed` fq lint (`not available` if the check could not run) and whether the repair was `skipped` or `run`. The table is also shown in the MultiQC report.

</details>

### Repaired samplesheet

`repaired_samplesheet.csv` lists the samples in `repaired` in the [samplesheet format](usage.md#samplesheet-input) of this pipeline and of other nf-core pipelines, so that the repaired reads can be given as `--input` to a downstream pipeline. Samples without any reads left, because all their reads were empty or could not be recovered, are not listed.

```csv title="repaired_samplesheet.csv"
sample,fastq_1,fastq_2
mysampleA,<output folder>/repaired/mysampleA_1.fastq.gz,<output folder>/repaired/mysampleA_2.fastq.gz
mysampleC,<output folder>/repaired/mysampleC.fastq.gz,
```

### FastQC

[FastQC](http://www.bioinformatics.babraham.ac.uk/projects/fastqc/) gives general quality metrics about your sequenced reads. It provides information about the quality score distribution across your reads, per base sequence content (%A/T/G/C), adapter contamination and overrepresented sequences. For further reading and documentation see the [FastQC help pages](http://www.bioinformatics.babraham.ac.uk/projects/fastqc/Help/).

<details markdown="1">
<summary>Output files</summary>

- `fastqc/`
  - `*_fastqc.html`: FastQC report containing quality metrics.
  - `*_fastqc.zip`: Zip archive containing the FastQC report, tab-delimited data file and plot images.

</details>

### MultiQC

[MultiQC](http://multiqc.info) is a visualization tool that generates a single HTML report summarising all samples in your project. Most of the pipeline QC results are visualised in the report and further statistics are available in the report data directory.

<details markdown="1">
<summary>Output files</summary>

- `multiqc/`
  - `multiqc_report.html`: a standalone HTML file that can be viewed in your web browser.
  - `multiqc_data/`: directory containing parsed statistics from the different tools used in the pipeline.
  - `multiqc_plots/`: directory containing static images from the report in various formats.

</details>

Results generated by MultiQC collate pipeline QC from supported tools e.g. FastQC. The pipeline has special steps which also allow the software versions to be reported in the MultiQC output for future traceability. For more information about how to use MultiQC reports, see <http://multiqc.info>.

### Pipeline information

<details markdown="1">
<summary>Output files</summary>

- `pipeline_info/`
  - Reports generated by Nextflow: `execution_report.html`, `execution_timeline.html`, `execution_trace.txt` and `pipeline_dag.html`.
  - Reports generated by the pipeline: `pipeline_report.html`, `pipeline_report.txt` and `software_versions.yml`. The `pipeline_report*` files will only be present if the `--email` / `--email_on_fail` parameter's are used when running the pipeline.
  - Reformatted samplesheet files used as input to the pipeline: `samplesheet.valid.csv`.
  - Parameters used by the pipeline run: `params.json`.

</details>

[Nextflow](https://docs.seqera.io/platform-cloud/reports/overview) provides excellent functionality for generating various reports relevant to the running and execution of the pipeline. This will allow you to troubleshoot errors with the running of the pipeline, and also provide you with other information such as launch commands, run times and resource usage.
